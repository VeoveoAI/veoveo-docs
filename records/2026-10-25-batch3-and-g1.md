## Incident: the control-plane reset dropped a repository

The deploy reset Hub's control-plane tables and reseeded them from a document saved
before the `time` repository existed, so Hub lost that repository's registration and
the person's `owner` assignment; Hub logged "the Lore repository … is not registered"
and `console__logs` answered 403. Lore was untouched. Restored the documented way:
`console__create_repository {id, name}` as the person, whom Lore records as creator,
which registers the repository again and assigns `owner`; then `console__watch`. A deploy
must publish changes to Hub's live control plane, never reset it.
