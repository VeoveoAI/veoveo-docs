## Incidents

- **A model call.** The builder, driving OpenCode's prompt in Chrome, queued a command after `!`.
  The `!` was refused by Claude Code's classifier, so the command was submitted to MiMo as a
  prompt. It was stopped within a second, but OpenCode had already titled the session, so at
  least one model call ran. No tool ran, and the prompt held no secret.
- **A Computer's home deleted.** For B2 the coordinator deleted the Computer's sandbox with
  the OpenShell CLI's plain `sandbox delete`. Hub's collection uses `keep_workspace`. The
  plain delete also removed the workspace claim `workspace-c4itoit73lpkaheav7u`. Its volume
  (`local-path`, reclaim `Delete`) and its directory went with it. The person's home was
  lost: OpenCode sessions, including G1's, settings and local clones. Lore, Artifacts and
  Hub's data were untouched. Entry created a new, empty home.

## Findings

- A failed start names the 120 s readiness deadline, not the sandbox's own reason
  (`ImagePullBackOff`).
- An operator's plain `openshell sandbox delete` of a Computer deletes its home.
- `console__computer` is offered to every profile, but Hub admits it only from the
  Computers profile. From the Mac it answers 401, as console's design says.
- OpenCode has no model-free way to list its tools. B12's mid-session change inside OpenCode
  rests on OpenCode's own `tools/list_changed` handling (`packages/core/src/mcp/client.ts`,
  and its test).
- VictoriaLogs: 9,994 "missing _msg field" records in 7 days, the last at 22:06:47 on 10-25;
  none since the change. Blank lines are rare enough that this window does not prove the
  change live. The coder's local run of the same image does.
