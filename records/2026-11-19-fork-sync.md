# Fork sync: rmcp 3.11, OpenShell v0.1.9, Lore v0.14.0, OpenCode 2.3.2, n8n 2.48.5

2026-11-18 to 2026-11-19. Every fork moved to its upstream's latest stable release, every consumer was
pinned to it, the installation was deployed in three steps, and the owner's Computer took one new Computer
version. RustSec's new chrono and humantime notices are accepted in every repository that reaches them.

Coordinator Claude Opus 5.5 in Claude Code; the OpenShell, Lore, OpenCode and n8n syncs were each done by one
worker agent on the same model, reviewed by the coordinator. Checks, images and deployment ran as unattended
scripts on the box (`~/k3s-builds/sync-20261118/`) and the Mac.

## Advisories

RUSTSEC-2026-0543 (chrono unmaintained) and RUSTSEC-2026-0542 (humantime unmaintained) appeared on 2026-11-17
with no patched release and failed every repository's `cargo deny`. Core, the SDK and the Hub use chrono
directly (about 177 files), and rmcp 3.11.0, oauth2 5.0.0, object_store 0.14.2, schemars, sqlx and
openshell-core depend on it; upstream issues are open (rmcp #1469, object_store #909, oauth2-rs #351,
OpenShell #5642). Each repository's `deny.toml` now accepts the notices it reaches, with a reason: chrono
everywhere, humantime in core, the Hub, Artifact and Media. OpenShell v0.1.9 no longer pulls in
rustls-pemfile, so the Hub's and both installers' RUSTSEC-2025-0134 exceptions were removed.

The workers' fork checks, each compared with an unmodified upstream checkout:
- **OpenShell:** workspace 7038 passed, 2 failed; server 2818 passed. Both failures also fail on v0.1.9.
- **Lore:** clippy clean; 8271 passed, 1 failed (a `lore-fuse` SIGINT test, which also fails on v0.14.0); smoke 1714 passed. `lore.toml` parses to the same settings.
- **OpenCode:** typechecks pass. Every suite's failures match unmodified v2.3.2, with the Mac's known shell and Node limits.
- **n8n:** agents 2592 passed, MCP integration 63, instance-ai 5811, cli 9888. 4 browser fixtures also fail on 2.48.5.

Unplanned fixes, each caused by an upstream change:

- rmcp 3.10/3.11 added response-limit tests expecting the text `UnexpectedServerResponse` where the fork's
  typed `HttpResponse { status, body }` applies; they were adapted inside the carried typed-rejection commit.
- rmcp #1446 makes a server's default `tools/list`, `prompts/list`, `resources/list` and
  `completion/complete` answer -32601 unless the capability is advertised. Six Hub `discovery_watch` tests
  used a stand-in server that advertised nothing; it now advertises tools. Real servers implement these.
- OpenShell v0.1.9's gateway refuses the driver key `additional_ca_bundle`; the installation now names
  `platform-destination-roots-v1` in the chart's `supervisor.network.additionalCaConfigMapName`, and the
  gateway's own destination-CA mount is gone.
- The Mac's first Bioma installer check ran the template installer's stale test binary. Both installers
  build a crate named `veoveo-installer` into the shared BuildKit target cache, and `git archive` gives files
  their commit time. The Mac checks now extract with fresh modification times.
