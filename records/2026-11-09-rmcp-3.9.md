# Every server on rmcp 3.9.0

rmcp 3.9.0 was released on 2026-11-05. On 2026-11-09 the fork moved to it, and every consumer, image, factory server and
Computer of the Bioma installation now runs on it.

## The fork

`VeoveoAI/rust-sdk` `veoveo/main` is `e8c8868`: upstream `main` at `f2b0ddf` (after `rmcp-v3.9.0`) with the fork's changes
replayed one commit each, as `VEOVEO_FORK.md` says. The old tip `d45f7f5` keeps the signed tag `veoveo-rmcp-3.8.0`, so every
commit that pins it still builds.

| Change | Outcome |
|---|---|
| Skill manifest boundaries (#1412) | Retired: upstream merged it in 3.9.0 |
| Task status through `subscriptions/listen` | Carried, `fc98f8f` |
| Typed HTTP rejections | Carried, `2c63963`. Upstream's new response limit (the security fix in "Merge commit from fork") conflicted; both enum variants are kept, the body is the one upstream reads within its limit, and upstream's response-limit tests expect the typed status and body |
| Two DEBUG logs | Carried, `b66b87d` and `3837839` |

rmcp's CI checks on the Mac: fmt, the three clippy runs, and tests with all features 1,119 passed, without `local`
1,692 passed, the library without default features 188 passed, the response limits with reqwest's charset 52 passed, and
the docs.
