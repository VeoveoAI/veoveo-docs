## The server

`VeoveoAI/veoveo-mcp-n8n` `1bcc115`, from the MCP template: slug `n8n`, port 8811, SDK
`24bd67b`. It registers with surfaces (public route `/n8n/hooks/`, 1 MiB, 600 a minute;
an app origin behind `n8n.editor`); starts n8n as its child on loopback with the design's
environment (PostgreSQL schema `n8n`, prefix `n8n_`, `PGOPTIONS=-c role=server_n8n`, owner
from the environment, push over SSE, blocks and exclusions); keeps the owner's password,
the encryption key and its API key under `/sandbox/state/n8n`; imports credentials;
applies `workflows/*.json` by file name; serves `n8n://workflows`, `n8n://workflow/{…}`,
`n8n://editor`. Its hooks and editor root answer 503 in this phase. The factory image is
the template's `rust:1.99.0-trixie` with node and n8n copied from the Debian fork image by
digest; `openshell/providers.yaml` requests `vv-factory-model`, which the control plane
grants the repository.

Its tests, on this Mac: 41 of 41 (`cargo nextest`), with fmt, clippy, deny, hack and
`sqlx prepare --check`; one test against a real n8n (stock 2.46.0 in Docker with the
fork's driver file mounted, as spike run 5) covered PostgreSQL ownership, the encrypted
credential and the create, keep, update and archive cycle. The repository's `check`
gate, run on the box with the Debian fork image, failed at its last step: `.sqlx` lacks
the core crates' queries that the gate's `prepare --all` expects; sent back with phase 2.

## Unplanned fixes, in Hub

- **Public routes and app origins used the wrong transport** (Hub `2470fca`). Both took the
  binary's bare client pool, which reaches `<sandbox>.internal:8800` over the network and
  failed in 5 ms (the hooks answered 502); MCP uses the catalog's pool, whose native
  forward reaches the instance's sandbox. The component tests reach their servers over
  local TCP, so they could not show it.
- **The app origin's entry missed the scopes** (Hub `c39d4b6`). The entry decided with the
  browser session's stored principal, which carries no scopes, so the live profile's
  required scopes refused the owner (`MissingScope`). The entry now decides as each request
  does: a bearer of the family through the Hub's profile authentication in process.

## Boundaries

- I6's refusal without `n8n.editor` is proven in Hub's component test, not in production:
  the one person tried holds it.
- The factory base policy admits every binary to any host on ports 80 and 443, so n8n is
  not yet confined to the hosts its policy names. An installation follow-up.
- Phase 2 is not deployed: runs as Tasks (I14), the bridge (I15), the editor (I16), the
  hooks' delivery.
